# Taste Bar

## Should Feel Like

- A serious software portfolio with playable evidence.
- Raycast-level utility density where tools are involved.
- A polished arcade cabinet where games and secrets appear.
- Fast, tactile, intentional, and specific.

## Should Not Feel Like

- A generic developer landing page.
- A novelty site where effects replace substance.
- A SaaS dashboard with fake metrics.
- A dark-mode template with interchangeable cards.
- A game portal that hides the developer's professional value.

## Interface Rules

- Make the primary action obvious on every page.
- Keep text compact and concrete.
- Use motion to clarify state or reward interaction, not to distract.
- Keep hidden features discoverable through fair clues.
- Keep cards and panels purposeful; do not frame every section as a card.
- Preserve keyboard and reduced-motion accessibility.

## Copy Rules

- Prefer proof over claims.
- Name the concrete thing built.
- Explain why the implementation matters.
- Avoid vague phrases like "innovative", "cutting-edge", and "passionate".

## Quality Bar

A change is strong only if it makes the visitor's next action clearer, makes a
working artifact easier to inspect, or makes the portfolio more credible.
